# Voice hook spec: `hook/morte-hook.js`

A Claude Code hook that turns Claude Code events into a Morte speech bubble
(through OpenPets) plus, sometimes, one of Morte's own voice barks. It
replaces the hooks OpenPets installs for Claude Code. Node ≥ 18, no
dependencies. It never fails a hook: every path exits 0.

## Why it replaces the OpenPets-managed hooks

The managed hooks speak from fixed pools in `@open-pets/agent-events`
("Done", "Hit a snag", "Approval needed"), and a bare reaction makes the
desktop app add its own generic line from `reaction-messages.ts`. Neither pool
is configurable, so the Morte hook sends `pet.say` with a message on every
event it handles. `install.js` removes managed entries (marker
`--openpets-managed`) and adds `node "<repo>/hook/morte-hook.js"` on six events,
`async: true`, `timeout: 5`. Running `openpets configure` re-adds the managed
hooks next to Morte's; re-running `install.js` removes them again.

## Event → category

| Claude Code event | Condition | Category | Reaction | Cooldown | Bark chance |
|---|---|---|---|---|---|
| `UserPromptSubmit` | | thinking | thinking | 20 s | 0.2 |
| `PreToolUse` | `Edit` / `Write` / `MultiEdit` / `NotebookEdit` | editing | editing | 20 s | 0 |
| `PreToolUse` | `Bash` / `PowerShell` matching the test regex | testing | testing | 20 s | 0.3 |
| `PreToolUse` | other `Bash` / `PowerShell` | running | running | 20 s | 0 |
| `PreToolUse` | `AskUserQuestion` | question | waving | 3 s | 1 |
| `PreToolUse` | anything else | (silent) | | | |
| `PermissionRequest` | | permission | waiting | 3 s | 1 |
| `Notification` | `permission_prompt` or "permission" in message | permission (deduped by the 3 s cooldown) | | | |
| `Notification` | `idle_prompt` or "waiting for your input" | idle | waving | 60 s | 1 |
| `Stop` | | success | success | 4 s | 0.7 |
| `StopFailure` | | error | error | 4 s | 1 |

Decided on purpose: a reply that ends with a question still fires `Stop` and
gets a "success" line. Only `AskUserQuestion` maps to "question".

Test regex: `test|tests|vitest|jest|pytest|phpunit|pest|mocha|npm test|pnpm test|yarn test|cargo test|go test|dotnet test` (word-bounded, first 300 chars of the command).

## Lines and clips

- `lines.json`: bubble text per category. **Original writing in Morte's voice,
  never game dialogue.** Every line must pass OpenPets' `validateSayMessage`
  (mirrored in the hook's `validMessage`, checked by `--check` and the tests):
  ≤ 140 chars, single line, none of `class import export const let var`
  (case-sensitive) or `=>`, no URL or path-like text, nothing matching
  `api key|secret|token|password|passwd` (case-insensitive).
- `clips.json`: `clips` maps clip sets (`thinking`, `working`, `permission`,
  `question`, `idle`, `success`, `error`) to game resrefs (committed).
  `clips.meta.json` holds each clip's `dialog.tlk` label and duration; it is
  generated by `extract_voice.py` and gitignored. Without it the hook assumes 1 s per clip.
  Editing/testing/running share the `working` set.
- The `ambientBored` / `ambientEngaged` clip sets (and the `ambient*` / `ambientQuips*` lines) are not used by the hook;
  they feed the idle plugin (`docs/idle-plugin-spec.md`). Same files, same audition page.
- `clips/<RESREF>.wav`: produced by `pipeline/extract_voice.py`, gitignored.

Clips were chosen by the game's own soundset labels ("Locked [Morte]",
"Lockpick Succeeded [Morte]", "Morte Bored 11"…), and each was checked to
decode as speech (spectral flatness 0.08–0.24). `MRT361` ("Item is
identified") decoded as noise and was dropped. Nobody has listened to them
in-session; `hook/audition.html` exists for that.

Picking: random from the pool, avoiding the last three picks for lines / last four
for clips. A bark is skipped while the previous one is estimated to still be
playing (duration + 0.6 s).

## OpenPets IPC (how the bubble gets there)

1. Read the discovery file `%APPDATA%\OpenPets\runtime\ipc.json`
   (macOS: `~/Library/Application Support/OpenPets/runtime/ipc.json`, Linux:
   `$XDG_CONFIG_HOME/OpenPets/runtime/ipc.json`; override with
   `OPENPETS_DISCOVERY_FILE`). Fields used: `endpoint` (Windows named pipe
   `\\.\pipe\openpets-…` or `tcp://host:port`), `token`.
2. Connect, write one JSON line:
   `{"id": <uuid>, "version": 1, "token": ..., "method": "pet.say", "params": {"message": ..., "reaction": ...}}`
3. Read one JSON line back (`{"ok": true, ...}`); 2 s timeout.

No `leaseId`, so the message goes to the **default pet** (Morte), not a
separate agent-pet window.

## Audio

Windows: detached hidden `powershell.exe` running
`(New-Object System.Media.SoundPlayer '<file>').PlaySync()` (~0.5 s start-up).
macOS: `afplay`. Linux: `paplay`. OpenPets has no audio channel for external
clients, so audio is outside the pet.

## Configuration and state

- `hook/config.json` (optional, gitignored; `MORTE_CONFIG` points elsewhere):
  overrides `speech`, `audio`, and per-category entries of `audioChance` /
  `cooldownMs`. The two maps merge, so `{"audioChance": {"success": 0.3}}`
  changes only "success".
- `MORTE_MUTE=1`: bubbles only. `MORTE_DEBUG=1`: log to the state dir.
- State: `%LOCALAPPDATA%\MorteVoice\state.json` (cooldowns, recent picks,
  audio-busy time); debug log `debug.log` next to it.

## CLI

```
node hook/morte-hook.js --test <category>   fire one category now (ignores cooldowns)
node hook/morte-hook.js --check             validate every line
node hook/install.js [--settings P] [--uninstall] [--dry-run]
```
